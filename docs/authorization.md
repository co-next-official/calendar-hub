# 認可モデル

## 原則

- 操作の主体は常に「ユーザー」。ブラウザはセッション Cookie、AI は API キーで本人を特定する。どちらで来ても同じユーザーとして扱い、権限を足し合わせない。
- 予定テーブルへのアクセスは `src/db/events.ts` だけが行い、全関数が `ownerId` を必須で受け取って条件に入れる。ルートハンドラーから直接テーブルを触らない。
- 権限外の予定は「存在しない」と同じ応答（404）にする。存在の有無も漏らさない。
- 同時編集は `version` による楽観ロック。古い `version` での更新は 409。

## 今あるもの（MVP）

| テーブル | 中身 |
| --- | --- |
| `users` | Google の `sub` で一意。メール・表示名・アイコン |
| `sessions` | Cookie のトークンは SHA-256 だけ保存。有効期限つき |
| `events` | `owner_id` 必須。終日は日付（終了排他）、時刻付きは UTC と IANA タイムゾーン。DB の CHECK でも形を強制 |
